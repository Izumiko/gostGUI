# gostGUI v1.9 阶段一（功能 + 界面）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **执行方式已定**：每个任务派一个 `deepseek-official/deepseek-flash` 子代理实现，任务之间由父代理验收（构建 + 自检 + 必要的截图），最后整体复审。

**Goal:** 给 gostGUI 加上工作目录、环境变量、PATH 解析、双向权限模型（专用 runner 转发 stdout）和中文化深/浅主题界面，产出 `gostGUI.exe` + `gostGUI.Runner.exe` + `config.json` 三个文件。

**Architecture:** UI 进程只在"权限匹配"时自己 `CreateProcess`；权限不匹配时拉起独立的 `gostGUI.Runner.exe`，由它创建子进程、重定向三流、挂 Job Object，并通过命名管道把输出按行回传给 UI。新增逻辑尽量做成无 UI 依赖的纯函数（解析/合并/编解码/启动参数组装），全部挂在 `--selftest` 上验证。

**Tech Stack:** .NET Framework 4.8、WinForms、System.Text.Json 11.0.0、Fody 6.9.3 + Costura.Fody 6.2.0（两个 exe 都内嵌依赖）、MSBuild（VS18）。

**Spec:** `docs/superpowers/specs/2026-11-11-gostgui-v1.9-design.md`（执行者必须同时读它；本计划只写"决定"，规格里的理由与取舍在 spec 里）

## Global Constraints

- 目标框架 `.NET Framework 4.8`，两个工程都 `<LangVersion>latest</LangVersion>`；不改目标框架。
- 产物必须是 **`gostGUI.exe` + `gostGUI.Runner.exe` + `config.json`**，不许出现第三方 dll 散落（依赖一律 Costura 内嵌）。
- 不新增第三方依赖（允许：System.Text.Json、Fody、Costura.Fody、Microsoft.NETFramework.ReferenceAssemblies）。
- 界面、日志、错误提示文案**全中文**；代码注释中文；类型/方法/字段名英文。
- `config.json` 必须向后兼容：只含 `name/enable/program/args` 的旧文件加载后新字段取默认值，行为与 v1.8 一致。
- 子进程输出一律按 **UTF-8** 解码（沿用现状）。
- 窗口尺寸/位置以 **DIP** 存储；布局下限 **1024×640 DIP**；日志每项上限 **1000 行**。
- 权限失败必须报错：**禁止**在提权/降权失败时回落到继承父进程权限。
- 构建命令（每条验证步骤都用它）：
  ```powershell
  & "C:\Program Files\Microsoft Visual Studio\18\Professional\MSBuild\Current\Bin\MSBuild.exe" gostGUI.sln /t:Restore /t:Build /p:Configuration=Release /v:m /nologo
  ```
- 自检命令（退出码 0 才算过，同时把 transcript 写到 `bin\Release\selftest.log`）：
  ```powershell
  & .\gostGUI\bin\Release\gostGUI.exe --selftest; "exit=$LASTEXITCODE"
  ```
- 本项目**没有**测试框架。所有自动化验证都加进 `SelfTest.cs` 的用例列表，走 `--selftest`。TDD 循环 = 先加断言（红）→ 实现 → 再跑（绿）。

## Review Focus

按"最可能咬到用户"排序，每条都钉在拥有该代码的任务上：

1. **程序写裸名、只有靠本项 env 追加 PATH 才找到**（`PATH=%PATH%;C:\tools` + `program: mytool`）→ Task 4 的 `Resolve_UsesEffectiveEnvironment` 用例。
2. **路径或参数含空格/引号**（`C:\Program Files\x\y.exe`、参数里已有 `"`）→ Task 4/5 的引号与 `cmd /d /s /c` 包装用例。
3. **子进程输出含中文、空行、超长行、或只有 stderr** → Task 7 的帧转义往返用例 + Task 8 的 smoke 断言。
4. **子进程启动即退出或启动失败（740/2/193）** → 状态不能卡在"运行中" → Task 6 的失败用例 + Task 8 的"exit 先于 started"用例。
5. **`config.json` 被手改成脏数据**（未知字段、类型不符、`env` 值为空串、`theme` 乱写）→ Task 2 的容错用例。

### Task 8: runner 全链路（RunnerMain + RunnerClient + runner-smoke）

**Files:** Create `gostGUI/RunnerClient.cs`；Modify `gostGUI.Runner/RunnerMain.cs`、`gostGUI/ProcessManager.cs`（权限匹配时也走 runner 的开关）、`gostGUI/Program.cs`（`--runner-smoke`）、`gostGUI/SelfTest.cs`

**Interfaces:**
- Produces: `RunnerSession`（见契约）；`RunnerMain` 支持 `--spec <base64>` / `--spec-file <path>`；`ProcessManager` 在 `GOSTGUI_FORCE_RUNNER=1` 时全部走 runner。
