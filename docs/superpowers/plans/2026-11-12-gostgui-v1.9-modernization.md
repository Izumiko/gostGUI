# gostGUI v1.9 阶段二（代码现代化 N1+D2）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **执行方式已定**：每个任务派一个 `deepseek-official/deepseek-flash` 子代理实现，父代理在任务之间跑构建 + `--selftest` 确认无退化，再做任务级复审。

**Goal:** 在**行为完全不变**的前提下，把 gostGUI v1.9 阶段一的代码现代化：语言档位与分析器、死代码清除、P/Invoke 收口、`keybd_event`→`SendInput`、数据层去 UI 耦合、把 4222 行的 `FormMain.cs` 与 6635 行的 `SelfTest.cs` 拆成按职责分区的文件、async 化与并发容器。

**Architecture:** 阶段一已完成并验证（27 个提交、`--selftest` 119/119、`--grok` 终审通过）。阶段二只动**结构与写法**，不动协议、配置格式、权限模型、UI 文案与布局。拆分优先用 partial class 与纯函数抽取，**不重写事件流**；每步结束必须构建绿 + 119 个用例零失败。

**Tech Stack:** .NET Framework 4.8、WinForms、System.Text.Json 11.0.0、Fody 6.9.3 + Costura.Fody 6.2.0、MSBuild（VS18）、Roslyn 分析器（`Microsoft.CodeAnalysis.NetAnalyzers`，仅开发期 `PrivateAssets=all`）。

**Spec:** `docs/superpowers/specs/2026-11-11-gostgui-v1.9-design.md` §11（N1+D2 的权威定义）；阶段一的计划与提交历史是行为基线。

## Global Constraints

- 目标框架保持 `.NET Framework 4.8`；**不新增运行时依赖**（分析器属开发期依赖，必须 `PrivateAssets="all"` + `IncludeAssets="runtime; build; native; contentfiles; analyzers; buildtransitive"`）。
- **行为零变化**：119 个 `--selftest` 用例必须全部保持通过；`--runner-smoke` 通过；四个已提交快照（96/150/200 深浅）在纯重构任务中**保持字节一致**（若某任务合法地改变渲染，必须在报告里解释并重新提交快照）。
- 不改 `config.json` 格式与语义、不改管道/协议帧、不改权限矩阵、不改 UI 文案与布局。
- 每个任务一个提交；功能与重构**不混提交**；任务内不得顺手做别的任务的清理。
- 构建：`& "C:\Program Files\Microsoft Visual Studio\18\Professional\MSBuild\Current\Bin\MSBuild.exe" gostGUI.sln /t:Build /p:Configuration=Release /v:m /nologo`（首次 restore 前清 `$env:http_proxy/$env:https_proxy/$env:no_proxy`）。
- 自检：`$p = Start-Process -FilePath .\gostGUI\bin\Release\gostGUI.exe -ArgumentList '--selftest' -Wait -PassThru; $p.ExitCode`。
- 不在无人桌面弹窗；视觉验证只用 `--ui-snapshot <dir>`。

## Review Focus

阶段二的风险全是"重构引入的静默退化"，按最可能咬人排序，每条钉在拥有该代码的任务上：

1. **partial 拆分后成员可见性/重名被 `new` 掩盖**（拆 `FormMain` 时旧事件处理器与基类成员同名，编译器只给 CS0114 警告）→ Task 5 必须做"警告零新增"检查。
2. **`Nullable enable` 用 `!` 抑制代替真正的空值处理**（把警告压下去而不是修好）→ Task 1 的 review 逐处检查 `!`。
3. **`keybd_event`→`SendInput` 后"Alt 击键换前台权"语义走样**（tray 双击还原可能不再置顶）→ Task 3 无法自动验证，必须写进人工验收清单。
4. **数据层"吞异常"改成"抛异常"后，异常逃到 UI 线程**（原来只 `Debug.WriteLine` 的地方抛到消息循环 → 全局异常弹框）→ Task 4 要求每个调用点都有明确处理。
5. **`ConcurrentDictionary` 替换手锁后"先查后改"竞态**（`StartProcess` 的"已运行就不启动"判断）→ Task 7 要求状态转换仍在锁内。

## 执行纪律

- 子代理只做自己任务，结束时必须构建 + `--selftest` 双绿；任何一步让 119 个用例变红都算失败，不得删断言或改用例名来"变绿"。
- 每个任务结束由父代理独立跑一次构建 + 自检，再派独立复审。
- 纯结构任务（5、6）如果中途发现某段代码无法在不改行为的情况下搬动，**停下来报告**，不要顺势重写逻辑。
- 阶段二是"行为不变"的重构：任何需要有感的行为调整都不属于本计划。
