# gostGUI v1.9 设计文档

> 主题：工作目录 / 环境变量 / PATH 解析 / 双权限模型 / 界面重排
> 状态：待人类伙伴批准
> 日期：2026-11-11

## 1. 意图与背景

gostGUI 是一个 WinForms 小工具（.NET Framework 4.8，Costura 打包成单文件 `gostGUI.exe`），用来把 `gost.exe` 这类命令行程序以配置的方式在后台跑起来，带托盘、开机自启、Job Object 崩溃清理和每项独立日志。

现有能力覆盖不到的场景有五个，来自使用者的直接诉求：

1. 每个配置项要能单独指定**启动目录（工作目录）**。
2. 每个配置项要能单独指定**启动时的环境变量**。
3. `Program` 要能写**裸命令名**（如 `gost`、`git`），从 `PATH` 里找。
4. 要能启动**需要管理员权限**的程序；并且本工具本身以管理员启动时，它拉起的子进程**除非显式要求**，否则不该继承管理员权限。
5. 界面要**美化**。

关键约束（来自使用者）：**普通权限和需要管理员权限的程序都要能实时看到 stdout**。这一条把"用 `runas` 直接起目标程序"的省事路线否掉了——`ShellExecute` 提权启动拿不到重定向输出，必须有一个中转进程替目标程序持有管道。

## 2. 现状（读代码得到的事实）

- `Common.cs`：`ConfigItem { name, enable, program, args }`；`ConfigData { autoRun, items }`；System.Text.Json，`UnsafeRelaxedJsonEscaping` + 缩进。
- `ProcessManager.cs`：`Process.Start` + `UseShellExecute=false` + `CreateNoWindow=true`，stdout/stderr 全部按 UTF-8 读；`WorkingDirectory` 被**写死**成 `Common.GetApplicationPath()`；启动前 `File.Exists(program)` 预检；子进程加入 `JobObjectManager` 的 Job（`KILL_ON_JOB_CLOSE`）；进程字典加锁。
- `FormMain.cs`：事件直连 UI；列表自己 owner-draw 画 ▶/■ 状态图标；双击图标启停；右键菜单新建/重命名/删除；托盘双击还原（`keybd_event` + `TopMost`，无 `AttachThreadInput`）；`FormClosing` 里取消关闭改为隐藏。
- `LogViewManager.cs`：每个配置项一个动态 `TextBox`，靠 `Visible` 切换；追加走 `BeginInvoke`；用 `EM_GETLINECOUNT` 数行，超过 500 行整段清空。
- `ConfigurationManager.cs`：`config.json` 读写，增删改名（重名拒绝），每次改动整表保存。
- `Program.cs`：`Directory.SetCurrentDirectory(exe 目录)`（解决自启动时 CWD 是 system32 的问题）；全局异常弹框。
- `FormMain.Designer.cs` + `FormMain.resx`：**30 多个控件的位置/尺寸全部以固定坐标存在 resx 里**，通过 `resources.ApplyResources` 应用；没有 DPI 感知（无 app.manifest），缩放屏上发虚。
- 构建：`MSBuild.exe`（VS18）`/t:Restore;Build /p:Configuration=Release` 通过，产物 `gostGUI/bin/Release/gostGUI.exe` + `config.json`。
- 仓库无测试工程、无 CI。

## 3. 目标 / 非目标 / 反目标

**目标**

- G1 每个配置项可设置工作目录（空 = 本工具所在目录，保持现有行为）。
- G2 每个配置项可设置环境变量（在父进程环境基础上增量覆盖）。
- G3 `Program` 支持裸命令名：按 `应用目录 → PATH` 的顺序查找，支持 `PATHEXT` 补全（`gost` → `gost.exe`），支持带引号、`%VAR%`、相对路径；界面上实时显示解析结果。
- G4 两向权限模型：普通启动的管理员项要提权运行；管理员启动的普通项要降权运行；两条路都必须有实时 stdout/stderr、可停止、可整树清理。
- G5 界面重排 + 深/浅主题（默认跟随系统，可手动切换），补 DPI 感知。

**非目标**

- 不做服务化、不做计划任务式启动、不做多用户/远程会话管理。
- 不保存管理员密码，不提供"每次静默提权"。
- 不改协议栈、不加 HTTP/代理配置等与本次诉求无关的功能。
- 不改 `config.json` 既有字段语义；升级后老配置必须原样可用。
- 不迁 .NET 10、不换 UI 框架：阶段二只做写法与结构现代化（见 §11）。

**反目标（做到也算失败）**

- 为了省事在提权失败时静默按父进程权限启动（违反"不继承管理员权限"）。
- 为了拿 stdout 而在子进程里套一层常驻控制台窗口或 cmd 中转（会引入黑窗、Ctrl+C、编码一堆问题）。
- 界面改成一堆无边框自绘窗口技巧，导致拖动/贴边/缩放/DPI 出问题。

## 4. 约束（Windows 侧事实）

1. Windows 子进程默认继承父进程的完整性级别（IL）；没有"降权参数"。
2. 从标准权限启动 `requestedExecutionLevel=requireAdministrator` 的程序会 `CreateProcess` 失败，`Win32Exception.NativeErrorCode = 740`（ERROR_ELEVATION_REQUIRED）。
3. 从提权进程启动"标准权限"子进程，必须借一个中等 IL 的令牌：常见做法是从 `explorer.exe` 复制主令牌，再 `CreateProcessWithTokenW`（需要 `SeImpersonatePrivilege`，提权进程自带）或 `CreateProcessAsUser`（需要 `SeAssignPrimaryTokenPrivilege` / `SeIncreaseQuotaPrivilege`，通常是提权后可用）。
4. `ShellExecuteEx` + `runas` 起的进程，其标准输出句柄**不可靠**（跨 seclogon，句柄表不通），所以提权目标必须由中转进程亲自 `CreateProcess` 并持有管道。
5. 提权后 UAC 弹窗无法合并：一个管理员项一次授权。
6. `CreateProcess` 对裸文件名会自己搜 PATH，但**不套用 `PATHEXT`**；`File.Exists("gost")` 也不成立。所以 PATH 解析必须自己做，且解析结果要用于存在性检查和日志展示。
7. 命名管道跨 IL：中等 IL 的服务器、提权 IL 的客户端（同一用户/在 Administrators 组）可以连接，默认 DACL 允许；不需要句柄继承，这对跨权限场景是关键优势。
8. 本机实测环境：Windows 11 26H2 (10.0.26300)，会话 1，屏幕 1536×960；当前 agent 进程为标准权限。

## 5. 方案选型

### 5.1 权限架构

| 方案 | 说明 | 取舍 |
|---|---|---|
| A 单 exe 双模式 + 命名管道 | `gostGUI.exe --runner <spec>` 作为中转 | 单文件发布不变；但 UI 代码与 runner 同工程，runner 启动会带上 WinForms 初始化的体积 |
| **B 独立 runner exe（已选）** | `gostGUI.Runner.exe --spec <base64>`，无 WinForms 依赖，只做"建进程 + 转发" | 发布形态变成两个文件；换来 rider 职责干净、启动快、UAC 弹窗明确显示 runner 名字、UI 与提权逻辑彻底隔离 |
| C 不用中转 | 提权项 `runas` 直起，输出落临时文件再 tail | 最省事，但日志延迟/粘行/编码乱，且子进程逃出 Job Object、工具崩了留孤儿；"都要 stdout"直接否掉 |

选 **B**。runner 是一份独立的、几乎不含 UI 的最小可执行文件，被两种"权限不匹配"的场景共用；UI 进程永远不持有需要跨权限传递的句柄（管道名走命令行），绕开 Windows 跨权限句柄继承的历史坑。

被否掉的备选：让 UI 始终以标准权限运行、禁止以管理员启动（不能满足 G4 的后半句）；用计划任务 `schtasks /RL LIMITED` 降权（慢、脏、要建任务）；用 `explorer.exe <path>` 借壳降权（参数传递不可靠，无法确认身份）。

### 5.2 界面方向

| 方案 | 说明 | 取舍 |
|---|---|---|
| A 只换肤 | 保留现有布局，只改字体/配色 | resx 里的固定坐标塞不进 3 个新输入框，撑不住 |
| **B 深色调重排 + 保留系统标题栏（已选）** | 代码化布局、卡片式分区、自绘扁平控件、主题切换、DPI 感知 | 工作量适中；标题栏交给系统，拖动/贴边/缩放零风险 |
| C 无边框自绘窗口 | 自定义标题栏、圆角、阴影 | 视觉最猛，但拖动/贴边分屏/最大化/缩放/DPI 全要自己写，坑最多 |

选 **B**。配色上做浅/深两套调色板，默认**跟随系统**（读 `HKCU\...\Themes\Personalize\AppsUseLightTheme`），顶部提供三态切换（跟随系统 / 浅色 / 深色），选择持久化到 `config.json`。

## 6. 详细设计

### 6.1 配置模型（向后兼容）

```json
{
  "autoRun": false,
  "theme": "system",              // system | light | dark，缺省 system
  "window": { "w": 1100, "h": 720, "x": -1, "y": -1, "max": false },
  "items": [
    {
      "name": "item1",
      "enable": true,
      "program": "gost",
      "args": "-L 127.0.0.1:8080 -F tls://abc.com:4000",
      "workDir": "",             // 空 = 本工具所在目录；支持 %VAR% 与相对路径
      "env": { "GOST_LOG": "debug" },   // 缺省/null = 不覆盖
      "runAsAdmin": false        // 缺省 false
    }
  ]
}
```

- 所有新字段可缺省；老 `config.json`（只有 name/enable/program/args）加载后新字段取默认值，行为与今天一致。
- `theme`、`window` 是全局 UI 状态，放在 `ConfigData` 上；损坏/越界值一律回落到默认。
- 保存策略沿用"每次改动整表保存 + 文件级锁"。

### 6.2 程序解析（G3）

新增 `ProgramResolver.Resolve(program, baseDir, effectiveEnv)`，返回 `ResolvedProgram { FullPath, Kind, Note }`，`Kind ∈ { Exe, Batch }`。**`PATH` 取自该项的"有效环境"（父进程环境 + 本项 env 覆盖），不是父进程原始 PATH**——否则用户写了 `PATH=%PATH%;C:\tools` 再填 `program: mytool` 会找不到，等于把刚配的东西判无效。管线顺序因此固定为：**建有效环境 → 解析 program → 解析 workDir → 启动**。

1. `Trim()`，剥掉成对的首尾引号，展开 `%VAR%`（取自父进程环境）。
2. 为空 → 错误"未设置程序"。
3. **带路径**（含 `\` 或 `/` 或盘符）：相对路径拼 `baseDir`；`GetFullPath` 规范化；存在则命中；不存在且没有扩展名，则按 `PATHEXT` 逐个补全再试。
4. **裸名**：候选目录 = [baseDir] + `PATH` 各项（跳过空项、展开 `%VAR%`、剥引号）；每个目录下先按原名试，无扩展名再按 `PATHEXT`（`.COM;.EXE;.BAT;.CMD`…）逐个试；先命中先赢。
5. 都没命中 → 错误"在应用目录与有效 PATH 中均未找到 xxx"，并把搜过的目录数与**有效** PATH 摘要写进日志（界面上那行提示同样按有效 PATH 判断，不能拿父进程 PATH 糊弄）。
6. `.bat`/`.cmd` 命中时 `Kind=Batch`，实际启动为 `cmd.exe /d /s /c ""<full> <args>""`；`.exe`/`.com` 直接启动。
7. 解析失败不阻断编辑，只在启动时报错；UI 在程序框下方用一行提示展示 `→ C:\...\gost.exe`（绿）或 `未找到（已搜索 PATH 的 N 个目录）`（红）。

解析结果的缓存键 = `program`，`PATH` 变化后（重新启动程序）自然刷新，不做热监听。

### 6.3 工作目录（G1）与环境变量（G2）

**工作目录**：`workDir` 空 → `Common.GetApplicationPath()`（与今天一致，避免升级后行为漂移）。非空 → 先展开 `%VAR%`，相对路径按应用目录解析，`GetFullPath` 规范化；启动前校验目录存在，不存在 → 日志报错并拒绝启动。UI 给"浏览…"和"取程序目录"两个鼠标操作。

**环境变量**：

- 配置文件里是对象（保持可读、可 diff）；UI 用"每行一条 `KEY=VALUE`"的多行文本框编辑，保存时解析成对象。
- 解析规则：跳过空行与 `#` 开头的行；按第一个 `=` 切分；键和值都 `Trim()`；键为空的行记为警告并忽略。
- 值里的 `%NAME%` 展开顺序：同项内**先出现的**键 → 父进程环境 → 原样保留（单次展开，不递归，避免环）。
- 合并语义：**增量覆盖**。以父进程环境为底（键名大小写不敏感，与 Windows 一致），逐项覆盖/新增；`PATH=%PATH%;C:\tools` 这种写法因此天然可用。
- 合并后的环境块总大小超过 32K → 报错并拒绝启动（Windows 硬限制）。
- runner 场景：spec 里只带**覆盖项**（已展开），runner 在它自己的继承环境上做同样的合并，避免把整个环境块塞进命令行。**这条是有意的取舍，不是疏漏**：UAC 提权的 runner 由提权代理创建，它的基础环境取自提权令牌，未必逐字等于 gostGUI 进程的环境（父 shell 里临时设的变量、提权时输入了别的账号等）。要逐字一致就得把整个合并后的环境块塞进 spec，那 `--spec-file` 会从边缘兜底变成常态路径，命令行长度、编码、注入面全跟着变复杂。结论：**保证"本项 env 覆盖一定生效"，不保证"基础环境与 UI 进程逐字相同"**；日志里对 runner 场景记一行实际的基础环境来源（继承自提权令牌 / 继承自标准用户令牌），便于排查"为什么这台机器上少了个变量"。

### 6.4 启动路径矩阵与 runner 协议（G4）

| 本工具 | `runAsAdmin` | 走哪条路 |
|---|---|---|
| 标准 | false | **直连**：UI 进程内 `Process.Start`（今天的行为） |
| 标准 | true | **runner + UAC**：`ShellExecuteEx(runas)` 拉起 `gostGUI.Runner.exe` |
| 管理员 | false | **runner + 降权**：从 `explorer.exe` 复制主令牌，`CreateProcessWithTokenW` 拉起 runner |
| 管理员 | true | **直连**：本来就有管理员权限 |

另有调试开关 `GOSTGUI_FORCE_RUNNER=1`：所有项强制走 runner（同权限，直接 `CreateProcess` 拉起），用于在不需要 UAC 的情况下验证管道与 runner 全链路。

**启动与自启语义（管理员项不自动弹 UAC）**：程序启动时的自动恢复和"开机自启"只拉起 `enable && !runAsAdmin` 的项；需要管理员的项被跳过，并在它自己的日志里写一行"已跳过：需要管理员权限，请手动启动"——不弹窗、不阻塞、也不静默消失。只有用户显式点"启动"或"全部启动"才走提权路径（每个这样的项一次 UAC）。`enable` 字段语义不变（"正在运行 / 上次是运行状态"），**不为这个需求新增配置字段**。

**spec（命令行传参）**：`gostGUI.Runner.exe --spec <base64url(UTF-8 JSON)>`，字段：

```json
{ "v":1, "nonce":"<guid>", "pipe":"gostgui.<guid>", "program":"C:\\...\\gost.exe",
  "args":"-L ...", "workDir":"D:\\...", "env":{"K":"V"}, "kind":"exe", "requestedAdmin":true }
```

base64 字符集不含空格，`lpParameters` 不需要额外引号；若编码后超过 8000 字符 → 改用 `--spec-file <临时文件路径>`（runner 读完即删）。spec 里带 `nonce` 用于握手校验。

**协议**：UI 是命名管道服务器（`NamedPipeServerStream`，`PipeDirection.InOut`，异步），runner 是客户端（15s 连接超时）；UTF-8 NDJSON，一行一条消息：

- runner → UI：`{"t":"ready","nonce":..}`、`{"t":"started","pid":N}`、`{"t":"out","e":"o"|"e","d":"..."}`、`{"t":"exit","code":N}`、`{"t":"error","d":"..."}`
- UI → runner：`{"t":"stop"}`

**管道与 spec 文件的 ACL（跨账号提权的兜底）**：管道服务器一律用显式 `PipeSecurity` 建，授予 **当前用户 + `BUILTIN\Administrators` + `SYSTEM`**；临时 spec 文件也显式设 ACL 给同样的主体。这样即使用户在 UAC 里**输入了另一个管理员账号的凭据**（runner 以那个账号运行，默认 DACL 只覆盖创建者，会连不上），提权路径仍然可用。代价是每个这样的子进程以那个管理员账号的身份运行——`%APPDATA%`、`%TEMP%`、映射盘、`workDir` 权限都按那个账号算，这是 Windows 的事实，日志里显式写一行"子进程身份：<账号名>"避免用户困惑。

**runner 职责**（`RunnerMain`）：

1. 解析 spec，校验 `program` 是全路径且存在。
2. 连管道（带 `nonce` 握手），失败即退出。
3. 建 Job Object（`KILL_ON_JOB_CLOSE`）+ `Process`（`UseShellExecute=false`、`CreateNoWindow=true`、UTF-8、重定向三流），启动后加入 Job。
4. 异步读 stdout/stderr，逐行转成 `out` 消息；退出时发 `exit`。
5. 后台线程读管道命令：收到 `stop` → 记下"用户停止"标记 → `TerminateJobObject`；读到 EOF（UI 消失/崩溃）→ 同样终止子进程后退出。
6. 自身退出前 `CloseHandle(job)`，兜底杀整树。

**UI 侧 `RunnerClient`**：

- 生成 GUID 管道名 → 建服务器 → `WaitForConnectionAsync`（UAC 场景 60s 超时，普通场景 15s）→ 拉起 runner → 收 `ready` 校验 `nonce` → 收 `started` 记录子 PID → 事件转发到 `ProcessManager` 的既有回调（`ProcessStarted` / `OutputReceived` / `ProcessExited` / `ProcessStopped`）。
- 停止：发 `stop` → 等 `exit`（超时 8s 后辅助 `Process.Kill` runner）→ 关管道。
- 管道断开/runner 异常退出 → 视为进程退出，日志注明"中转进程异常退出（错误码 X）"。

**提权启动细节**：`ShellExecuteEx`，`SEE_MASK_NOCLOSEPROCESS`，`lpVerb="runas"`，`lpFile=runner 绝对路径`，`lpParameters="--spec <b64>"`，`lpDirectory=应用目录`；`NativeErrorCode=1223 (ERROR_CANCELLED)` → 日志"已取消管理员授权"；其他失败 → 报错误码 + 提示。

**降权启动细节**：

1. 找当前会话的 `explorer.exe`：`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → `OpenProcessToken(TOKEN_QUERY|TOKEN_DUPLICATE)` → `GetTokenInformation(TokenElevation)` 确认非提权 → `DuplicateTokenEx(..., TokenPrimary)`。
2. `CreateProcessWithTokenW(token, 0, runnerPath, cmdline, 0, NULL, baseDir, &si{DESKTOP="winsta0\\default"}, &pi)`；失败 `1314` → 打开并启用 `SeAssignPrimaryTokenPrivilege`/`SeIncreaseQuotaPrivilege` 后重试 `CreateProcessAsUser`。
3. 两条路都失败 → 日志明确写"无法以标准权限启动：请改用标准权限运行 gostGUI"，**绝不**回落到继承管理员权限。
4. 所有句柄 `finally` 关闭。

**失败与错误码映射**（统一写进日志，便于排查）：`740` 需要管理员（提示勾选）、`1223` UAC 取消、`1314` 权限不足、`2` 文件不存在、`5` 拒绝访问、`193` 不是有效可执行文件（`.bat` 误按 exe 启动时提示）。

### 6.5 界面设计（G5）

## 10. 风险与未决

1. **凭据提权（UAC 里输入另一个管理员账号）后的语义差异**：管道与 spec 文件已按 §6.4 显式授权 Administrators，连接不再是问题；但子进程会以那个管理员账号身份运行，`%APPDATA%`/`%TEMP%`/映射盘/工作目录权限都按那个账号算。日志里显式写"子进程身份：<账号名>"，README 也注明。若实测发现这类机器上仍有连接问题，备选是把管道方向反过来（runner 建服务器、UI 作客户端连），协议不变。
2. `ShellExecuteEx` 的 `lpParameters` 长度上限未在文档中明确，故用 8000 字符阈值 + 临时文件兜底。
3. RichTextBox 在超高频输出（每秒数百行）下仍比 TextBox 重，靠批处理 + 1000 行上限缓解；若实测仍卡，退回单色 TextBox（着色可后续再做）。
4. 子进程输出按 UTF-8 解码（沿用现状），非 UTF-8 输出会出现替换字符；未在本次诉求内，README 里注明。
5. 一次"全部启动"里若含多个管理员项，会连续弹多次 UAC（无法合并）；属于 Windows 限制，UI 上不额外优化。

## 11. 阶段二：代码现代化（N1 + D2）

**硬约束**：不改行为、不迁框架、不动发布形态（`gostGUI.exe` + `gostGUI.Runner.exe` 两个文件）。阶段二的验收标准是"功能验收清单在重构前后逐条一致"，不是"看起来更新"。

### 11.1 语言档位与静态检查

- `<LangVersion>latest</LangVersion>`。现在没写这个属性，编译器按 net48 默认停在 **C# 7.3**，`switch` 表达式、`using` 声明、`record`、file-scoped namespace、目标类型 `new`、模式匹配全部不可用——这是"写法现代化"最先要拆的墙。
- `record` / `init` 在 net48 上需要 `IsExternalInit` 的 polyfill（一个 20 行的内部类型），加上即可。
- `<Nullable>enable</Nullable>`：**新写的文件一律开**，老文件逐个补 `#nullable enable` 并修警告，最后全库开启。一次全库开会瞬间刷出几百条警告，反而没人看。
- 分析器：`Microsoft.CodeAnalysis.NetAnalyzers` + `<AnalysisLevel>latest</AnalysisLevel>` + 一份 `.editorconfig`（缩进、`var` 偏好、命名规则）。先以警告形式输出，不设 `TreatWarningsAsErrors`（net48 + 旧代码会直接卡死构建）。

### 11.3 结构与并发（D2 的主体）

- **`FormMain` 拆控制器**：`MainForm`（只做布局装配与事件转接）+ `ConfigListController`（列表、选中、重命名、排序、复制/删除）+ `DetailEditorController`（程序 / 参数 / 工作目录 / 环境变量 / 管理员开关 + 解析提示）+ `LogViewController`（每项日志视图、着色、批量刷新）+ `TrayController`（托盘、还原、菜单）+ `StartupController`（自动恢复、全部启动、开机自启）。
- **数据层不再弹 UI**：`Common.LoadJson`、`ConfigurationManager.RenameItem` 里的 `MessageBox` 全部去掉，改为返回结果（`LoadResult { Ok, Error, Items }`）或抛 `ConfigException`；由界面层统一提示。`SaveToFile` 里 `Debug.WriteLine` 吞掉失败的写法同样去掉。
- **async 化**：管道读写、runner 等待、进程停止全部 `async Task`，不再用裸 `Thread`；`StopAsync(TimeSpan timeout)` 先请求、再等、超时才杀。
- **并发容器**：`Dictionary` + 手写 `lock` → `ConcurrentDictionary<ConfigItem, LaunchSession>`；但**状态转换仍要在锁内完成**（`ConcurrentDictionary` 解决不了"先查后改"的竞态，这点不能为了现代化而退步）。
- **P/Invoke 收口**：所有 `DllImport` 进一个 `NativeMethods` 文件，按 DLL 分组，能返回 Win32 错误的统一包成 `Win32Exception`；句柄能用 `SafeHandle` 的就用。
- **`keybd_event` → `SendInput`**：`keybd_event` 官方已被 `SendInput` 取代；"一次 Alt 击键换取前台切换权"的行为保持不变。
